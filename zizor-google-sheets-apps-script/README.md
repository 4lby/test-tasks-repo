# Система учёта товаров и продаж — Google Sheets + Apps Script

Тестовое задание на вакансию «Ассистент программиста» (Зизор, отклик на rabota.by).
Выполнено 07–08.09.2026.

## Суть задачи

Компания ZIZOR дала готовый Google-шаблон с двумя листами — «База товаров» и «Журнал продаж» — и файл
`helper functions.gs` с готовыми функциями. Требование: **не дублировать готовый функционал**,
все решения писать в `Code.gs`. Нужно было закрыть пять задач и обработать ошибки ввода.

Листы и колонки в шаблоне:

| Лист | Колонки |
|---|---|
| База товаров | Артикул, Название, Категория, Цена, Остаток, Мин. остаток |
| Журнал продаж | Дата, Артикул, Количество, Сумма (авто), Статус (авто) |

## Что сделано

Все пять задач закрыты одной функцией обработки строки плюс двумя отдельными:

| # | Задача | Реализация |
|---|---|---|
| 1 | Авторасчёт суммы продажи (Цена × Количество) | `processSaleRow_()` |
| 2 | Проверка наличия и списание остатка, статус «Выполнено» / «Недостаточно товара» | `processSaleRow_()` |
| 3 | Список товаров с остатком ≤ минимального | `checkLowStock()` |
| 4 | Статистика за день: сумма и количество успешных продаж | `getDailySales(date)` |
| 5 | Триггер `onEdit` + форматирование ячеек | `onEdit(e)`, `colorRow_()` |

**Обработка ошибок:** пустой артикул, нечисловое или неположительное количество, ненайденный артикул,
нечисловая цена → статус «Ошибка данных» или «Артикул не найден» и красная заливка строки.
Некорректная дата → понятное исключение с указанием ожидаемого формата.

**Ключевые технические решения:**

- Готовые функции `helper functions.gs` (`findProductByArticle`, `updateProductStock`, `parseDate`,
  `formatDate`, `setCellColor`, `getSalesSheet`, `getProductsSheet`, `isNumeric`) используются
  повторно, дубликатов в своём коде нет.
- Триггер реагирует **только** на лист «Журнал продаж» и **только** на колонки Дата / Артикул /
  Количество. Это защита от зацикливания: автозаполненные ячейки Сумма и Статус не вызывают
  повторный расчёт.
- Сравнение дат сделано по году/месяцу/дню, а не по строке — иначе «01.11.2025» и «1.11.2025»
  считались бы разными днями.
- Парсер даты понимает три вида ввода: объект `Date`, строку `ДД.ММ.ГГГГ` и серийный номер дня
  Google Sheets (например `45962` = 01.11.2025).

**Бонусы сверх ТЗ:**

- `getMonthlyStats("MM.YYYY")` — статистика за месяц с разбивкой по дням.
- `onOpen()` — меню в таблице: проверка низких остатков, статистика за день и за месяц.
- `sendLowStockEmail()` — письмо владельцу при достижении минимального остатка.
- `setupValidations()` — data validation: артикул выбирается списком из базы, количество ≥ 1.
- `reprocessAllSales()` — пересчёт всех строк журнала одной кнопкой (нужно, если строки
  заполнялись вручную, а триггер их не видел).

## Стек

Google Sheets, Google Apps Script (JavaScript, ES5-совместимый синтаксис), SpreadsheetApp,
MailApp, data validation, simple triggers.

## Как установить

1. Сделать копию присланного шаблона таблицы.
2. Расширения → Apps Script.
3. В файле `Code.gs` удалить содержимое и вставить код из этого репозитория.
4. `helper functions.gs` не трогать — решение использует его функции.
5. Сохранить, перезагрузить таблицу: появится меню «Тестовое задание».
6. В редакторе один раз запустить `reprocessAllSales()`, чтобы пересчитать примеры из шаблона.

## Как проверить

| Проверка | Ожидаемый результат |
|---|---|
| В журнал добавить строку: дата, существующий артикул, количество 2 | Сумма = Цена × 2, статус «✓ Выполнено», остаток в базе уменьшился на 2 |
| Указать количество больше остатка | Статус «✗ Недостаточно товара», остаток не меняется, строка красная |
| Указать несуществующий артикул | Статус «Артикул не найден» |
| Указать пустое или нечисловое количество | Статус «Ошибка данных» |
| Меню → «Проверить низкие остатки» | Список товаров, где Остаток ≤ Мин. остаток |
| Меню → «Статистика за день» → `01.11.2025` | Сумма и количество успешных продаж за день |
